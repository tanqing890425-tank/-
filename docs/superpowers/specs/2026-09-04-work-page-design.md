# Work 独立页面设计说明

## 1. 目标

为现有个人作品集增加独立的 `/work` 页面，用于集中展示五个项目视觉。页面以当前网站已经落地的视觉规范、组件样式、字体、颜色和动效为主要依据，以 Figma 节点 `3778:1270` 的页面结构和内容排布作为次要参考。

## 2. 已确认的设计方向

- Work 使用独立、可直接访问的 `/work` 地址。
- 采用 Vite 多页面结构，不引入新的路由依赖。
- 首页保持现有单页内容与锚点行为。
- 顶部导航、底部导航和首页 MORE 入口都能进入 Work 页面。
- Work 页面复用当前网站的 Header、Footer、Logo、项目图片、字体、颜色变量和 reveal 动效。
- Work 页面只展示项目列表，本次不创建项目详情页，也不添加没有真实目标地址的卡片链接。

## 3. 页面架构

项目保留现有首页入口 `index.html`，新增 `work/index.html` 作为第二个 Vite HTML 入口。两个入口分别挂载首页应用与 Work 页面应用，共享全局样式和公共组件。

生产构建应至少输出：

- `dist/index.html`
- `dist/work/index.html`

这样 `/work` 可以由静态服务器解析为 `/work/index.html`，不依赖 SPA 回退规则，也不会因页面刷新而丢失路由状态。

## 4. 组件边界

### 4.1 公共框架

`Header` 和 `Footer` 增加当前页面参数，用于控制导航高亮。公共导航数据按页面地址输出：

- About：首页根路径 `/#top`
- Work：独立路径 `/work`

首页 Header 中 About 高亮；Work 页面 Header 中 Work 高亮。页脚链接与顶部导航保持相同地址，但不需要重复设置 `aria-current`。

### 4.2 项目数据

将当前 `SelectedProjects` 内部的五项图库配置移到共享数据模块。首页精选项目与 Work 页面从同一数据源读取图片、标题、说明和标签，避免两个页面出现顺序或内容不一致。

共享项目项至少包含：

- 唯一标识
- 图片资源
- 项目名称
- 简短说明
- 标签列表
- 可访问的图片替代文本

### 4.3 Work 页面主体

新增 `WorkPage` 和 `WorkGallery`：

- 页面标题：`WORK`
- 副标题：`从业务结构到视觉系统，让每一次触点保持一致`
- 五个项目按 Figma 参考顺序排列
- 项目图片上方不叠加标题；名称、说明和标签常驻图片下方
- 项目单元使用语义化 `article`，不模拟不可用的链接

## 5. 视觉规则

### 5.1 设计优先级

发生冲突时按以下顺序处理：

1. 当前网站已确认的设计规范与用户后续修改
2. 当前公共组件和设计令牌
3. Figma 页面结构、间距和内容关系
4. Figma 中的绝对坐标与临时生成代码

### 5.2 桌面布局

- 页面背景沿用 `#070708`。
- 版心沿用当前 `.shell`，最大宽度 1400px。
- Header 高度与当前网站一致。
- Work 主体标题距页面顶部 200px；移动端缩减为 130px，不复制 Figma 的绝对定位。
- 项目区为两列网格，列间距 20px、行间距 48px。
- 项目图片沿用当前网站的 `16 / 9` 比例，而不是 Figma 的固定 690×400 像素框。
- 项目名称桌面端使用 22px，与用户刚确认的项目标题规范一致。
- 项目说明与标签沿用当前正文、弱化文字和标签胶囊样式。
- 项目列表结束后保留 120px 间距再进入公共页脚。

### 5.3 移动布局

- 在现有移动断点体系内切换为单列。
- 图片保持 `16 / 9`。
- 项目标题在 18–20px 范围内响应式调整。
- 项目说明和标签允许自然换行，避免横向滚动。
- Header、Footer 继续使用当前移动端规则。

## 6. 交互与动效

- Work 页面主体元素沿用当前 `.reveal` 动效：进入延迟 300ms，缓动时长 1100ms。
- 向下滚动时渐入，向上离开视区时渐出，行为与首页一致。
- 项目图片悬停时沿用当前 `scale(1.035)` 的克制缩放，不增加模糊或明度变化；标题和标签保持常驻，不能依赖悬停才能读取。
- 支持 `prefers-reduced-motion`，关闭非必要动画。
- 页面加载时将滚动位置定位到顶部。

## 7. 链接行为

- 首页顶部 Work：`/work`
- 首页底部 Work：`/work`
- 首页 MORE：`/work`
- Work 页顶部 Work：`/work`，并标记为当前页面
- Work 页顶部和底部 About：`/#top`
- 品牌 Logo：`/#top`

所有地址使用普通链接。即使 JavaScript 未运行，浏览器仍会请求正确的首页或 Work HTML 文档。

## 8. 可访问性

- Work 主体使用 `main` 与具名 `section`。
- 页面只有一个一级标题。
- 每个项目图片提供与项目内容对应的替代文本。
- 项目列表使用语义化列表或带明确标题关联的文章集合。
- 当前导航使用 `aria-current="page"`。
- 键盘用户可以访问所有真实链接，不为非交互卡片添加 `tabIndex`。

## 9. 验证标准

自动验证：

- 首页和 `/work` 均能独立渲染。
- 构建产物包含两个 HTML 入口。
- Header、Footer 和 MORE 的链接地址正确。
- Work 页面导航状态正确。
- Work 页面展示五个项目，且顺序、图片、标题、说明和标签来自共享数据。
- 桌面为两列，移动端为一列；图片比例保持 `16 / 9`。
- Work 项目标题符合桌面 22px、移动 18–20px 规则。
- 现有首页测试继续通过。

视觉验证：

- 在 1920px 宽度下与 Figma 的层级、版心、双列节奏和页脚位置一致。
- 在当前浏览器宽度下无溢出、错位或导航状态错误。
- 在移动宽度下正文、标签与图片自然排布，无横向滚动。

## 10. 范围边界

本次包含独立 Work 列表页、共享数据整理、公共导航适配、首页入口更新、响应式样式和测试。

本次不包含项目详情页、CMS、筛选器、分页、搜索、后台管理或新项目素材制作。后续增加详情页时，可在共享项目数据中补充详情路径并将对应卡片升级为真实链接。
