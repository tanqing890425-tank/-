# Work Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone `/work` portfolio page from the approved Figma structure while keeping the existing website's visual system, components, typography, assets, and motion as the primary source of truth.

**Architecture:** Convert the Vite project into a two-entry multi-page build with `index.html` for the homepage and `work/index.html` for Work. Both entries share Header, Footer, project data, styles, and reveal behavior; the Work entry adds a focused `WorkApp` and `WorkGallery` without adding a routing dependency.

**Tech Stack:** React 19, Vite 7, JavaScript, CSS, Vitest, Testing Library

**Spec:** `docs/superpowers/specs/2026-09-04-work-page-design.md`

## Global Constraints

- The existing website's confirmed visual system and later user revisions override conflicting Figma details.
- Figma node `3778:1270` controls page hierarchy, two-column composition, and project ordering only where it does not conflict with the current site.
- The public Work address is `/work`; do not add React Router or another dependency.
- Reuse the existing logo, five project images, colors, typography, Header, Footer, project tag styling, and reveal behavior.
- Desktop project imagery remains `aspect-ratio: 16 / 9`; mobile uses one column and title sizing `clamp(18px, 5vw, 20px)`.
- Desktop Work project titles are `22px`.
- Reveal delay remains `300ms` and transition duration remains `1100ms`.
- Project cards are not links until real detail destinations exist.
- The current workspace is not a Git repository. Do not initialize Git without user authorization; use verification checkpoints instead of commit commands.
